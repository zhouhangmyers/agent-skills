# 业务分支建模

## 何时读取

当同一接口通过 `kind`、`mode` 等字段区分业务行为，且各分支具有不同必填项或互斥字段时，使用本节判断如何组织输入类型。

## 判断方式

- 先列出各分支实际需要的字段，以及真正共享的语义。
- 某字段在一个分支中必填、在另一个分支中没有意义时，优先分别定义分支类型，由明确的类型标记选择。
- 不用占位字符串、无意义空值或伪造默认值凑出统一结构；同名字段含义不同，也不应仅为复用而合并。
- 可使用联合类型、分支 Schema 或语言已有的等价机制；字段约束由对应分支声明，校验函数保留必要的跨字段业务规则。

## 示例：立即发送与定时发送

立即发送只需要正文：

```json
{"kind": "immediate", "content": "通知正文"}
```

定时发送还需要发送时间：

```json
{"kind": "scheduled", "content": "通知正文", "send_at": "2027-01-01T09:00:00Z"}
```

若业务明确规定只有定时发送接受发送时间，则定时分支要求 `send_at` 必填，立即分支不接受该字段。调用方不必为立即发送填入 `"unused"`，也不需要借助没有业务含义的空值才能通过公共结构的校验。

## 适用边界

合法的缺省、继承、未知或无关联状态可以使用可选字段，不因字段可选就机械拆分类型。多个分支共享结构与字段语义时，也可以继续使用同一模型。

按实际差异采用足够的类型，无须增加目录、服务或框架。修改既有协议时，核对调用方、派生协议、界面和持久记录的影响；已有外部契约与兼容要求应纳入方案，不借此扩大任务范围。
